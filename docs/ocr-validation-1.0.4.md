## 人工对照

参照文字来自人工查看原扫描图；重庆正文也与官方网页核对。Linn 的上游 `linn.txt` 自身含 OCR 错误，未直接当作真值。以下是在预先选定的完整区域上计算 `1 − 字符编辑距离 / 真值字符数`，统一 Unicode、大小写，忽略空白和标点，仅计字母、汉字与数字。它不衡量标点、数学公式或整本书的准确率。

| 对照区域 | 字符数 | r2 错误数 | r3 错误数 | r3 字符准确率 |
| --- | ---: | ---: | ---: | ---: |
| Turing 第 1 页完整引言段 | 729 | 0 | 1 | 99.86% |
| 重庆第 1 页完整正文段 | 112 | 0 | 0 | 100.00% |
| 重庆第 2 页完整文字区，含标题与序号 | 333 | 12 | 6 | 98.20% |
| Linn 完整左栏 | 936 | 0 | 0 | 100.00% |
| Linn 完整右栏 | 889 | 3 | 0 | 100.00% |

按词框分栏统计会掩盖栏间顺序错误，因此另检查实际缓存的整页文字顺序：r2 左右栏交错，r3 两栏主体顺序通过。说明书的全宽区域附近仍有标题归属误差，不能把表中数值解释为版面完全还原。

## 修正和边界

- Tesseract.js 默认使用单文字块模式；改为自动页面分区，修复双栏逐行串接。依据：[官方 FAQ](https://github.com/naptha/tesseract.js/blob/master/docs/faq.md)。
- 识别画布提高到目标 300 DPI，单边不超过 3600 像素、总量不超过 900 万像素；串行使用并释放。依据：[Tesseract 图像质量文档](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)。
- 比较相同页上的两种语言顺序后采用简体中文优先、英文同时识别；中文正文改善，英文引言仍有 1 处字母误识别。旧机器缓存重新识别，用户手动校正不覆盖。
- 本机本轮每页约 1.2–6.6 秒；包含每个文件首次加载模型，后续读取直接命中缓存。不同设备、页数和扫描质量会改变耗时。
- 红章覆盖区域和密集数学公式仍有明显错误。OCR 适合让印刷正文进入选择、检索、引用流程，不能替代对公式、印章或低清文字的人工核对。

## 本地复核

下载文件、逐页结果和人工对照保留在忽略提交的 `tests/reports/real-scans/`，不会进入应用包或公开附件。`manifest.json` 记录原件 SHA-256、页号与准备方法；`ground-truth.json` 记录区域和人工转录。

```sh
node scripts/test-real-scans.cjs
python -X utf8 scripts/score-real-scans.py
```

端到端读取测试另支持把 `FOLIO_REAL_SCAN` 设为上述 Turing 图片副本，再运行 `scripts/test-v104.cjs`，验证文件导入、OCR 搜索、选文、批注、重新打开、文字校正与加入提问。其余界面和格式回归仍使用可重建的合成样本。
