# V1.0.5 · 文件夹拖入、持续聊天与理解自测

日期：2026-11-08。基于 V1.0.4 r3，构建 r2。

## 导入

把文件夹或文献拖到 Folio 窗口即可导入本机副本，无需先打开导入选择器。递归读取子文件夹、保留相对路径，并在左侧文件夹树中显示；原文件不改写。同名文件位于不同子目录时分别保留。支持 PDF、DOCX、TXT、MD 与 Markdown，跳过隐藏项目和不支持的格式。每次最多 2,000 篇、单篇最多 200 MB；不可读项目会报告。

拖放事件中同步取得文件系统句柄，再异步遍历。旧版目录接口会持续读取批次，避免 Chromium 一次只返回 100 个条目导致漏导。拖入单张 PNG、JPEG、WebP 或粘贴截图会进入提问引用区，等待补充问题和发送。

## 同一聊天与 1M 上下文

只有画布右上角的“＋”新建聊天。换选段、拖入新问题、翻页、换文献、回文献库、打开作品都保留同一聊天。旧问答在画布上方按轮次展开，包含各轮文献来源；新回答完成后滚动到最新结果。每次先显示最近 20 轮，可继续展开更早记录，模型历史不受这个显示数量影响。

聊天独立保存到 IndexedDB，不受“自动整理对话为笔记”开关影响；重启恢复问答、原文、当前画布与小测作答。工作区备份包含当前聊天，较大聊天不写入 localStorage。点击“＋”会使旧请求失效，迟到回答不能回填新聊天。

移除最近 6 轮、8,000 字符、单条 48,000 字符及代理最近 16 条的限制。应用将单聊天请求预算设为 **1,000,000 tokens**，同时为输出预留空间。发送完整历史和各轮引用，不自动摘要或截断。用字符构成估算 tokens，界面带“≈”，不是服务商 tokenizer 或计费统计。传输上限为 32 MiB，单张发送图片压缩后最多 4 MiB。

服务商决定模型实际上下文窗口。把应用预算设为 1M 不会扩展短上下文模型；超过本地预算或服务端上限时保留聊天并明确提示，允许用户换模型或点击“＋”。不能将固定本地响应测试视为某个在线模型已通过 1M 质量验证。

## 图片识别

设置 → AI → 图片读取提供自动、视觉、仅本地 OCR 三种模式。自动识别常见视觉模型系列；自定义兼容服务可显式选择视觉。视觉模式将当前引用图片与历史引用图片送到所选服务，使用高清图片内容块；Claude 原生接口转换为 base64 image block。

支持扫描 PDF 来源页、框选的原图区域和拖入／粘贴的图片。扫描页附带 OCR 文字与原图，模型被要求核对公式、上下标、表格与图例，指出无法辨认的符号。文字模型继续使用本地 OCR；纯图片没有可识别文字时提示切换视觉模型或补充内容。图片随问答保存在本机，可在后续问题中继续引用。

这不保证所有图片中的文字都能准确识别。低清、手写、倾斜扫描、小字及复杂公式仍可能出错。本版验证了原图确实送达接口、内容块兼容性和本地 OCR 运行，未用付费在线模型做识别准确率评估。V1.0.4 的真实扫描评估仍见 [OCR 记录](ocr-validation-1.0.4.md)，不把旧结果当作本版视觉模型的准确率。

## 小测

每轮回答后提供“检验一下”：一道选择题或一道填空题。模型根据该轮问题、原文与讲解出题，返回结构化内容，经过格式和边界校验。选择题有 2–4 个不同选项与一个答案，填空题有一个空与简短参考答案。

提交或主动查看后才显示答案与解析。选择题按选项判定；填空题匹配模型提供的等价写法并统一大小写、空白和全半角。未匹配时提示对照解析，不把字符串不相同当成严格数学判错。题目与作答结果随聊天保存。出题会调用当前模型服务，判定与展示解析在本机完成。

## r2 · 长回答布局修复

修复回答与小测重叠：原回答区沿用 flex:1，在长回答超过可用高度时，容器被压缩而正文继续向外绘制。历史、回答、小测现按实际内容高度顺序排列，共用外层纵向滚动；长公式在自身区域横向滚动。空画布和加载状态仍保留自身占位。

回归使用多头注意力长公式和 8 段长回答，验证正文边界不超过容器、小测位于正文之后、整个面板不产生横向溢出。覆盖窄窗口、历史展开、追问、小测题目与反馈、125% 缩放、深色展开画布和重启。运行 `npm run test:v105-layout`，证据：`tests/reports/v105-layout/result.json`。
